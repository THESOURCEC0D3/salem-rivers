# HANDOFF — Salem Rivers church website

A warm-start guide for whoever picks this up next (Codex, Cursor, a human, or future-me).
Read this, then `AGENTS.md`, then `Church-architecture.pdf`, then `design-system/salem-rivers/MASTER.md`.

---

## 1. What this is

A website for a **Nigerian Pentecostal church** in **Port Harcourt, Rivers State** ("Salem Rivers").
The entire site has **one job: compel a first-time _physical_ visit.** The livestream is always a
subordinate fallback, never a co-equal call to action. The authoritative spec is **`Church-architecture.pdf`**
(repo root) — read it; it explains the strategy behind every page.

**Core principle:** almost everything funnels to **Plan Your Visit** (`/visit`), and the site is
**WhatsApp-first** — there are **no contact forms anywhere** (an unsure visitor won't fill one; WhatsApp is
lower friction and how people actually reach out locally).

## 2. Stack & the one hard rule

- **Next.js 16.2.9** (App Router), **React 19**, **TypeScript**, **Tailwind CSS v4**.
- ⚠️ **`AGENTS.md` rule (non-negotiable):** this is a non-standard Next.js whose APIs may differ from training
  data. **Read the relevant guide in `node_modules/next/dist/docs/01-app/` _before_ writing Next.js code**
  (fonts, `<Image>`, metadata, layouts, etc.). Codex reads `AGENTS.md` natively.
- Tailwind v4 uses `@theme` tokens in `app/globals.css` (not a `tailwind.config`). Custom tokens become
  utilities (`bg-primary`, `text-foreground`, `font-serif`).

## 3. Run & verify

```bash
npm run dev            # local dev → http://localhost:3000
npx tsc --noEmit       # type-check (must be clean)
npm run build          # production build (must succeed; all routes prerender static)
npm run start          # serve the build to smoke-test
```
There are no automated tests; verification = tsc clean + build green + eyeball the pages at
375 / 768 / 1024 / 1440 px.

## 5. Design system in one screen

- **Identity:** warm, community, a touch of reverence. **Royal purple + warm gold on ivory.**
- **Colors:** primary `#6D28D9` (purple), accent `#B45309` (gold), bg `#FFFCF7` (ivory), text `#2A1A33`
  (plum-charcoal), WhatsApp `#25D366`. Full table in `MASTER.md`.
- **Type:** headings **Fraunces** (warm serif), body **Nunito** — both via `next/font`.
- **Light theme only** (deliberate — a coherent, tested single theme beats a half-tested dark mode).
- **Rules:** SVG icons only (`app/components/icons.tsx`), **no emoji as icons**; `cursor-pointer` on
  clickables; visible focus rings; 150–300ms transitions; 44px touch targets; `prefers-reduced-motion`
  respected globally; mobile-first (cheap Android, patchy data) → optimize images, sub-3s.

## 7. Key patterns & conventions (reuse these)

- **`app/components/Section.tsx`** + **`Container.tsx`** — page section + width wrapper (use for new sections).
- **`Button.tsx`** — primary/secondary/whatsapp/ghost variants. (Many CTAs are hand-rolled `<a>`/`<Link>`
  where a dark-hero or custom treatment was needed — match the nearest sibling's classes.)
- **`PhotoPlaceholder.tsx`** — warm gradient stand-in for a missing photo, with a label of what goes there.
  **Swap for real images** as they arrive.
- **Real images:** background/hero images use string `src` + `fill` + `object-cover` + a scrim (cropping is
  desired). **Flyers / natural-ratio images** use a **static import** + `h-auto w-full` + `placeholder="blur"`
  so the whole image shows uncropped (see `home/NextEvent.tsx`). Event flyers are keyed by event id in
  **`app/components/eventImages.ts`** (`covenant-week` → `Event1.jpeg`).
- **`YouTubeFacade.tsx`** — lite-embed (loads the real iframe only on tap). Built for Watch reuse.
- **`whatsappLink(msg)`** — builds `wa.me` deep links with a prefilled message. Use for every WhatsApp CTA.
- **`ReadyToJoin`** (in `home/`) — the purple closing CTA, reused on About/Events.

## 8. Deferred work (with design notes)

### a) The real Watch page (`/watch`) — biggest deferred piece
Two states (architecture doc §3.5), currently a "Coming soon" placeholder:
- **Live** (Sunday during service): "We're live now" + the channel **live_stream** embed
  (`https://www.youtube.com/embed/live_stream?channel=<channelId>`, auto-resolves to whatever is live) +
  a Facebook link. Load the real player immediately (the visitor chose to watch).
- **Not-live** (other 166h): `YouTubeFacade` of the latest service video id + the next-live time.
- **Live detection — schedule-based, no API:** a **client** component reads the current weekday + time in
  **`Africa/Lagos`** (via `Intl.DateTimeFormat`, timezone fixed to the church, not the visitor). If it's
  Sunday inside the service window → live, else not-live. **SSR-safe:** render not-live by default, flip in
  `useEffect`. Limitation: schedule-based, not a real broadcast check (cancelled service → embed shows
  YouTube's own offline message). Only add the YouTube Data API later if the manual rhythm becomes a chore.
- Needs in `church.watch`: `channelId`, `latestServiceId`, `schedule {dayOfWeek, start/end, timeZone}`.
- Keep the physical visit primary at the top; watching is the fallback.

### b) Events & About photo heroes
Precious is adding `public/images/events-hero.jpg` (a **wide crowd/congregation photo — NOT the flyer**) and
`public/images/about-hero.jpg` (congregation/community). Plan: build a reusable **`PageHero`** (optional
background image + `hero-scrim` + white text; falls back to the warm gradient) and use it on
`events/EventsHero.tsx` and `about/AboutHero.tsx`.
